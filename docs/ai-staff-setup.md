# ИИ-штаб BYTEAM

Пять ролей: менеджер, скаут, тренер, аналитик, спортивный психолог. Каждая имеет отдельную историю диалога, инструкции и примеры запросов. Общий контекст вводится пользователем; передача до пяти задач и событий включается отдельным флажком. Истории и контекст находятся в памяти страницы и очищаются при её обновлении. Диалоги психолога автоматически другим специалистам не передаются.

Менеджер и тренер могут предложить одну задачу. Перед записью пользователь проверяет название, исполнителя и дату. Задача сохраняется через авторизованный клиент Supabase в `tasks`; необходимы проект и таблицы с корректными RLS-политиками. Запись должна быть разрешена только участнику с соответствующими правами на команду. Чтение и создание задач в реальном проекте требуют отдельной проверки после подключения.

Для живой модели нужны `OPENROUTER_API_KEY`, `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`. Не коммитьте значения. Ключ OpenRouter используется только на сервере; доступ к модели требует подтверждённой Supabase-сессии. `OPENROUTER_MODEL` задаёт модель; значение по умолчанию — `openrouter/free`. Доступность и поддержку JSON-ответа выбранной модели нужно проверить у провайдера. Если модель или конфигурация недоступны, возвращается явно обозначенный справочный шаблон для выбранной роли.

API валидирует роли, сообщения и предложения задач. Автономных изменений сайта нет. Внешние базы игроков и турниров, автоматический разбор демок и изменения календаря ещё не реализованы. Спортивный психолог — ИИ для обсуждения взаимодействия и подготовки; он не заменяет квалифицированного специалиста и экстренную помощь.

Перед публичным подключением модели требуется инфраструктурная квота запросов на пользователя/команду и общий лимит расходов. Текущая авторизация не является ограничителем частоты запросов. Свободный пользовательский доступ не означает неограниченную бесплатную обработку у провайдера.

Проверки: `npm test`, `npm run lint`, `npm run build`. В браузере проверьте выбор пяти ролей, независимость историй, общий контекст, метку справочного ответа, предложение задачи, форму подтверждения и сценарии отсутствующей конфигурации. Для живой модели проверьте серверную авторизацию; для реальной записи используйте разрешённую тестовую команду.
