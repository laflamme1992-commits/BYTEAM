# Плейбук BYTEAM

Раздел `/playbook` находится в боковом меню и доступен без подключения ИИ. Запись содержит карту, сторону, тип, закупку, зону, колл, краткую идею, роли игроков со стартовыми позициями и задачами, упорядоченные шаги полного раунда, гранаты с привязкой к ролям, ориентиры, способы броска, тайминги, ссылки на видео, запасной план, заметки и метки.

Ответ тренера или аналитика в ИИ-штабе можно открыть в редакторе плейбука кнопкой «Проверить и добавить в плейбук». Перед сохранением нужно проверить карту (по умолчанию Mirage), сторону, содержание и назначения. В справочном режиме источник помечен как шаблон. Ответ длиннее 6000 символов не обрезается молча: пользователь получает просьбу сократить его. Сохранение такого ответа происходит локально только после подтверждения.

Есть поиск по названию, коллу, ролям, позициям и раскидкам; фильтры карты, стороны и типа; избранное; копирование записи; удаление с подтверждением. Режим «Перед игрой» оставляет памятку и позволяет выбрать одну роль. Показываются её действия, её гранаты и общие шаги. Это ручной плейбук: автоматическая проверка раскидок на актуальном патче и ИИ-генерация стратегий в этой версии не подключены.

Локальный режим работает через localStorage этого браузера. Записи не привязаны к аккаунту, не синхронизируются автоматически и могут быть потеряны при очистке данных браузера. Для резервной копии и передачи команде используйте JSON-экспорт. Экспорт содержит весь выбранный плейбук, включая закрытые стратегии; распространяйте его осознанно. Импорт доступен локально, создаёт копии с новыми ID и не перезаписывает существующие записи. Ограничения: 250 записей, файл до 3 MB, до 8 ролей, 30 шагов и 20 гранат в одной записи. Повреждённый импорт отклоняется целиком; повреждённое локальное хранилище не перезаписывается. При изменении открытой записи в другой вкладке сохранение проверяет её версию.

Командное хранилище: для настройки проверьте фактическую схему существующей `public.teams` и примените `supabase/migrations/20261026_playbook.sql` через принятый в проекте процесс миграций. SQL предполагает UUID в `teams.id` и `teams.captain_id`; до применения нужно подтвердить это на реальном проекте. Миграция добавляет только новую таблицу, индекс, триггер версии и RLS-политики. Запись доступна только авторизованному капитану соответствующей команды. В текущем проекте нет проверенной связи аккаунтов участников с командой, поэтому общий доступ всем игрокам не выдумывается. До появления membership-модели игроки могут обмениваться экспортом. Обновлять разрешено только `data`; перенос записи между командами запрещён правами на столбцы. Обычный update/delete содержит проверку `updated_at`, чтобы обнаруживать устаревшую версию.

После подключения Supabase и применения миграции вкладка «Команда» станет доступна капитану. Локальные записи не загружаются автоматически: отдельная кнопка копирует выбранную запись в командное хранилище. При отказе сети локальная копия не удаляется. Переключение хранилищ не смешивает их данные. Миграция выполнена на локальной тестовой PostgreSQL-совместимой базе PGlite с явно заданной UUID-схемой: проверены чтение/запись капитаном, изоляция чужой команды, запрет анонимного доступа, неизменяемость team_id и конфликт версий. Серверный режим и RLS не проверены на реальном Supabase без реквизитов; перед использованием необходимо отдельно проверить разрешённую запись капитаном, отказ чужому пользователю, конфликт версий, удаление и изоляцию двух команд. Не используйте service-role ключ в браузере.

Команды проверки: `npm test`, `npm run lint`, `npm run build`. Браузерный сценарий: создать запись с ролями/шагами/гранатами; сохранить; обновить страницу; проверить поиск/фильтры; выбрать роль в памятке; изменить порядок шагов; экспортировать; импортировать копию; проверить ошибку повреждённого импорта; удалить запись с подтверждением. Отдельно проверьте клавиатуру, телефон и отказ localStorage. Шаблон раунда содержит учебные заглушки ориентиров, а не обещание проверенной тактики.
